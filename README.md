# Elijah Silverman

Personal site and portfolio. A static site built with [Astro](https://astro.build): a home page with the work, a docs-style résumé, and no client framework. The only JavaScript is small inline scripts for the hero, the Double Down demo, and the copy buttons.

## Run it

```bash
npm install
npm run dev       # http://localhost:4321
npm run build     # type-checks, then writes static files to dist/
npm run preview   # serves dist/
npm run resume:pdf  # with dev or preview running: prints /resume to public/resume.pdf
```

Requires a patched Node: 22.23.4+, 24.22.1+ or 26.12.1+ (the October 21, 2026 security releases). `.node-version` pins 24.22.1 for fnm, nvm and similar tools.

## Where things live

```
src/
├── data/site.ts          # name, links, roles, education, toolbox: edit copy here
├── data/resume.ts        # the résumé; /resume, /resume.md and the PDF all come from it
├── pages/index.astro     # home
├── pages/resume.astro    # docs-style résumé with contents, Markdown copy and PDF download
├── pages/resume.md.ts    # the résumé as Markdown
├── components/
│   ├── Hero.astro        # variable-width name with the pointer ripple
│   ├── Work.astro        # project stages and write-ups
│   ├── DoubleDownDemo.astro # playable offline round of Double Down
│   ├── ProjectText.astro # shared project text block
│   ├── About.astro       # timeline and facts
│   └── Contact.astro     # email, socials, footer
├── assets/work/          # project screenshots (Astro converts these to AVIF/WebP)
├── assets/fonts/         # Anybody and Instrument Sans, both OFL
└── styles/global.css     # color tokens, type scale, buttons
public/
├── og.png                # social share card
└── resume.pdf            # generated by npm run resume:pdf
```

## Adding a project

Project write-ups are in `src/components/Work.astro`. Each big project gets a `.feature` block with its own stage (styled in the colors of that project) and a `ProjectText`. Smaller ones go in the `.earlier` grid. Put screenshots in `src/assets/work/` and render them with `<Picture>` so they ship as AVIF and WebP.

## Updating the résumé

Edit `src/data/resume.ts`. The page and the Markdown update on the next build. To refresh the PDF, run `npm run dev`, then `npm run resume:pdf` (it uses your local Chrome; set `CHROME_PATH` if it lives somewhere unusual), and commit `public/resume.pdf`.

## Deploying

`npm run build` produces a fully static `dist/` that any static host can serve. `vercel.json` sets the framework to Astro for Vercel. Set `SITE_URL` (or deploy on Vercel, which provides the production domain) so canonical and Open Graph URLs are absolute.

## Design notes

- Type: Anybody (display, using its 50 to 150% width axis) and Instrument Sans (text).
- Color: limestone paper `#edeee8`, navy ink `#121a2e`, ultramarine signal `#2d46f5`. Dark mode follows the system.
- The two lines of the name use different widths so they set to the same measure. Moving the pointer over the name widens nearby letters and narrows the rest, so each line keeps its length.
